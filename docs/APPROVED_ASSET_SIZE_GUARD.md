# Early size validation for approved local chart assets

The independent preview server checks that every requested image or font is
listed in the approved SHA-256 manifest. Its verifier previously called
`readFileSync` on an entire file before checking the manifest byte count.
An accidentally replaced or oversized file could therefore cause a needless
full-file allocation before being rejected.

## Change

`readSafeAsset(root, path, expectedBytes?)` optionally takes the expected
manifest length. After its existing path and symlink checks, it compares the
regular file's `lstatSync().size` to the expected length **before reading**.
`verifyApprovedAssetPack` supplies the approved `record.bytes`.

The existing SHA-256 and post-read byte-count checks are retained: they
reject altered files of the same length and files changed between stat and
read. This is an early-rejection/memory-usage safeguard, **not** a guarantee
against all filesystem races or against malicious local collaborators.

## Compatibility

- Existing two-argument `readSafeAsset(root, path)` callers behave as before.
- Valid files and the public `verifyApprovedAssetPack` result are unchanged.
- Size-invalid files still fail with the existing manifest-mismatch diagnostic.
- No change to chart rendering, asset URLs, PNG export, approval policy, host
  origins, Angular builds, or VirgoStars/Astrolabio devices.
- No asset binaries or fonts are included.

## Tests

```sh
npm ci
npm run test:approved-pack
npm run test:local-assets
npm run verify:angular
```

The Node regression checks a matching synthetic file, direct early size
rejection, mismatched manifest metadata and same-size hash corruption. The
test uses locally generated bytes, not real chart artwork. Browser, e-ink
and approved-artwork visual parity remain separate validation gates.
